Based on a session, we should be able to restart a similar session. This can be useful when the MCP server has been updated and the session is no longer in a meaningful state. We should be able to start a new session with the same model and MCP server configuration as the original session as well as the same first prompt. This helps repeating simple tests when the MCP server is updated.

Based on the specific turn of a session we should be able to spawn a new session with the same model and MCP server configuration as the original session as well as the same history of up until that turn. This way is it possible to experiment with alternative prompts based on a single "deterministic" context. This is a quite comon feature in many chatbot interfaces.
